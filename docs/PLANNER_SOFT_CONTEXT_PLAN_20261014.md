# Soft Planner Context

## GOAL
Remove local content-size rejection while retaining efficient context projection, scientific checks, billing safeguards and the existing fit.

## Acceptance Criteria
- Default context and HTTP byte limits are None; optional-history soft target remains 270000 bytes.
- Necessary content above the target is dispatched, not rejected locally. Provider limits/timeouts and scientific admission still apply.
- Original evidence, source safety, parent identities and full canonical champion recipes remain intact.
- User-selected preservation: no fit cancellation; own-user automatic handover at safe drain boundary.
- Tests, saved D247 replay and sealed server qualification prove removal; activation readback must distinguish staged from live.

## Research
- Existing tools: guard projection, typed validation, HTTP transport receipts, lifecycle wrapper, systemd handover. No new dependencies.
- Primary local contracts are guard/install_guard, research_planner_context, transport classifier and sealed adapter; this is a policy correction, not new ML research.

## Root-Cause Baseline
- Evidence inventory: config/state, live metrics/readbacks, D247 error 300387>300000, 760 completed/39 failed/one optimizing probit fit, source size checks and own-user service inventory.
- Proven: a local guard rejects mandatory context after optional trimming; no provider call was made. Both default context and request hard limits exist.
- Likely: retained scientific/index metadata grows across completed trials. Possible: provider context limits later; not this failure.
- Disproven: D247 is an OpenRouter outage or paid request. Billing is reconciled.
- Missing evidence: next paid decision and long-term provider capacity cannot be guaranteed by local tests.
- Mutation boundary: fix/planner-remove-content-cap; clean guard, adapter, owned tests/docs and own handover unit only. Preserve dirty files and the HKJC acquisition unit.
- Remediation mapping: disable local rejection defaults, keep soft compaction, qualify with stress tests and actual failed evidence, deploy after fit completion.
- Not done: raising the cap slightly, disabling safety checks, claiming stress-test bytes are normal production payload, or claiming staged code is active.

## SOTA, Standards, And Best Practices
- Use built-in JSON/Pydantic and existing efficient projection. Separate optimization target from admission failure.
- Preserve provider constraints and bounded retries; no new planner calls solely for testing. The 900KB fixture is synthetic and mocked.
- Reject silently dropping safety or scientific identity to satisfy arbitrary byte thresholds.

## Dependency and Tooling Preflight
- Install or repair commands: no install needed; .venv pytest, git, SSH and systemd exist.
- No UI change; browser smoke is not applicable. Real external blockers: access or preservation boundary; durable handover handles the latter.

## Fulfillment and Readback Proof

## Armageddon Mode
- Large scope: oversized necessary metadata, compactable repeated histories, idempotent replay, explicit test-only bounded mode, unknown billing, malformed inputs, invalid proposals and transfer races.
- Must-fix: loss of safety data, cancelled fit, weakened comparison gates or unrelated service mutation.

## Generality Guardrail
- Existing mechanism: shared guard defaults and existing compaction. Recurrence likelihood high; general mechanism decision is soft-target projection rather than per-campaign cap patches.

## Regression Guardrails

- Touch surface: guard, adapter, owned tests/docs and new one-shot unit. Protect retry ceiling, probit runtime, memory limit, cost traces and other services.
- Atomic units: implementation/tests, qualification, deployment/readback.
