# Planner Actionable Feedback

## GOAL
Improve proposal reliability with exact bounded matched-control repair guidance; deploy in the IMA user without cancelling productive fits.

## Acceptance Criteria
- Rejections identify proposal, parent, differing values and legitimate repair choices.
- Graph outer-primary override precedence is explicit before paid calls.
- Blend-only corrections and honestly declared joint tests pass; no silent recipe mutation.
- Two-call ceiling, costs/tokens and scientific gates remain unchanged.
- Qualified live release and new decision readback prove rollout, or a real blocker is recorded.

## Research
- Reuse Pydantic decisions, proposal audit and bounded repair loop; no new dependency or planner.
- Primary local contracts: proposal_audit semantic comparison, research_executor outer-primary binding and openrouter_orchestrator correction loop.

## Root-Cause Baseline
- Evidence inventory: server status, D241 decision/provider responses, usage receipts, guard/audit/executor source and config/state readback.
- Proven: D241 changed outer Benter l2 from 0.001048550555018385 to 0.041030125528818434 and max_iter from 4847 to 3525 while declaring pipeline_composition only. Outer parameters override the primary graph node during execution.
- Proven: rejection reports only top-level fields, with generic exception text truncated at 2000 characters; no exact repair choices.
- Likely: unclear parameter precedence and generic errors contribute to repeated mismatches. Better feedback cannot guarantee model obedience.
- Possible: provider/context errors later; not this observed cause. Disproven: token/cost delivery failed; D241 accounting was delivered.
- Missing evidence: efficacy across future paid calls must be measured, not inferred from tests.
- Mutation boundary: fix/planner-actionable-feedback; clean guard/tests/docs and own-user handover only. Protect dirty modules and other services.
- Remediation mapping: request contract explains binding; structured errors give exact restore-or-joint choices; replay preserves comparison checks.
- Not done: suppressing errors or automatically changing axes, scientific claims or model settings.

## SOTA, Standards, And Best Practices
- Use existing typed validation and machine-readable path/value errors. Preserve original responses and deterministic comparison checks.
- Local validated execution contracts are primary evidence; no arbitrary code execution or extra framework needed.
- Reject automatic scientific-intent rewriting and unbounded paid retries.
